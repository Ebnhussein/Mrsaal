# أخطاء الإدخال وتأكيد الهوية

## المكوّن المشترك

`public/assets/validation.js` و`validation.css` محمّلان في صفحات الموقع العام باللغتين، الأداة، حساب البريد المباشر، ولوحة الإدارة. جرى اختبار إدراجهما عبر مسارات توليد الصفحات، بما فيها login/signup/contact/admin.

- نماذج HTML الحالية والجديدة، بما فيها التي ينشئها JavaScript، تستفيد من مستمع مركزي لأحداث submit وinvalid.
- الخانة الناقصة أو غير الصحيحة تُعلّم بإطار ورسالة نصية تحتها؛ لا يعتمد التوضيح على اللون وحده.
- أول خانة خاطئة تستقبل التركيز وتظهر في منتصف الشاشة. يُحترم تفضيل تقليل الحركة.
- تصحيح خانة يزيل خطأها فقط. وصف الخانة الأصلي لقارئات الشاشة يظل محفوظًا.
- القيود: required، البريد، الحد الأدنى/الأقصى لطول النص، نطاق الأرقام والزيادة، صيغة الرابط والنمط، رقم التسجيل بكود الدولة، تطابق تأكيد كلمة المرور، تفاصيل التواصل.
- الحقول المعطّلة والمخفية والاختيارية الفارغة لا تمنع التقديم. الموافقات المطلوبة تُعلّم عند مربع الموافقة.
- لا تُرسل بيانات النموذج عند وجود خطأ. قواعد الخادم والصلاحيات وحدود الاستخدام تظل مطبقة بصورة مستقلة.

## التغطية

| المنطقة | ما يغطيه التحقق |
|---|---|
| الدخول والتسجيل واستعادة/تغيير كلمة المرور | الحقول المطلوبة، صيغة البريد، طول كلمة المرور، تطابق التأكيد، رقم الدولة، الشروط، موضع CAPTCHA |
| تواصل معنا في الموقع الأساسي AR/EN | الاسم والبريد والقسم والرسالة؛ تفاصيل لا تقل عن 10 حروف |
| تذاكر الدعم والردود | العنوان والتفاصيل والحدود المطلوبة، بما في ذلك النماذج المنشأة داخل البوب أب |
| المساعد | نص السؤال مطلوب وحده الأقصى |
| إدارة المستخدمين | أرقام الحدود المطلوبة ونطاقها؛ البحث الاختياري لا يُفرض عليه محتوى |
| إدارة المقالات والتحديثات | الحقول المطلوبة بالعربية والإنجليزية وأطوالها المحددة في النماذج |
| ردود الإدارة | الرد مطلوب وحده الأقصى |
| تجربة OpenWA القديمة | نص رسالة الاختبار والموافقة المطلوبة |
| حذف الحساب | تبقى كتابة DELETE والتأكيد الصريح؛ زر الحذف معطّل حتى اكتمال الشرط |
| CV خارج نماذج HTML | توجيه لحفظ النص أو رفع السيرة عند الحاجة؛ لا يُفرض رفع جديد على صاحب نسخة محفوظة |
| استيراد الشركات | وجود الملف، عمود الاسم، عمود بريد أو هاتف، عدم استخدام العمود نفسه لأكثر من بيان |
| أسلوب الكتابة | خانة الشركة التجريبية، أمثلة الكتابة الناقصة لتحليل الأسلوب |
| منصات AI | المفتاح إذا لم يُحفظ سابقًا، الموديل الأساسي، أولوية صحيحة؛ الرجوع لخطوة الخانة قبل التركيز عليها |
| معاينة الرسائل واعتماد مسودات الحملة | نص الرسالة، موضوع البريد عندما تكون القناة Email |
| الجدولة | موعد مستقبلي عند اختيار الجدولة، أو موعد اختياري صالح في نافذة الحملة |
| ربط واتساب | تحقق الرقم والموافقة السابق؛ تأكيد الهوية أصبح بوب أب |

أعطال الشبكة أو نفاد رصيد AI أو رفض صلاحية Gmail ليست دليلًا أن حقلًا ناقص؛ تظل أخطاء تشغيل برسالة مناسبة. التحقق في الواجهة لا يثبت ملكية الهاتف ولا يغني عن التحقق في الخادم.

## قواعد التطوير للإضافات الجديدة

1. للنموذج العادي: استخدم form وlabel والقيود الصحيحة required/type/min/max/minlength/maxlength. المكوّن المشترك يغطي النماذج الديناميكية أيضًا.
2. للأزرار خارج form: استدعِ `MrsaalValidation.check([{field, test, message}])` وأوقف التنفيذ إذا رجعت false. اجعل test يقرأ القيمة الحالية ليختفي الخطأ مع التصحيح.
3. إذا كانت الخانة داخل خطوة مخفية، افتح خطوتها قبل التحقق. لا تُظهر خطأ في خانة لا يستطيع المستخدم الوصول إليها.
4. للأخطاء الخاصة بخانة محددة: `MrsaalValidation.error(field, message)`؛ وبعد حلها `clear(field)`.
5. لا تستخدم alert/confirm/prompt الأصلية لنوافذ مرسال. استخدم المكوّن المصمم.

## بوب أب تأكيد الهوية

`MrsaalDialog.identity()` يستخدم نافذة dialog مصممة بعنوان «خطوة أمان قبل تغيير الربط»، الشرح، زر متابعة باستخدام Google، «مش دلوقتي»، وX. Escape والإلغاء لا يغيّران الربط ولا يبدآن تسجيل الدخول. لا يحدث الانتقال إلا بعد الموافقة. لا يظهر شريط تأكيد هوية مكرر خارج النافذة. عند إغلاقها يمكن إعادة محاولة الإجراء نفسه لفتح التأكيد. أخطاء الرقم والموافقة تظهر تحت الخانات فقط دون ملخص عام مكرر. طريقة QR/الرقم تُحفظ للرجوع لإعدادات الربط؛ لا يُحفظ كود الربط أو مفتاح الخدمة.

## حصر النوافذ غير المصممة

الحصر السابق وجد **8 مواضع** لتأكيد المتصفح الأصلي: فصل واتساب ومساره الاحتياطي، فصل Gmail، حذف ربط AI، حذف الشركات، مسح السجل، إلغاء بقية الحملة، وحفظ مرجع الكتابة. كلها حُوّلت إلى UI مرسال في commit `5c21a0f`.

بعد هذا التحديث: **صفر استدعاءات أصلية لـ alert/confirm/prompt في شيفرة الإنتاج المفحوصة**. تأكيد الهوية نفسه أصبح نافذة مصممة أيضًا. نوافذ Google وصلاحيات المتصفح ومنتقي الملفات واجهات خارجية، لا يمكن تصميمها من CSS مرسال.

هذا حصر مصدر واختبارات سلوك؛ الاختبار البصري الفعلي لكل نافذة ومقاس شاشة يحتاج مراجعة بعد النشر.

## تجربة النشر

- جرّب التسجيل فارغًا، بريدًا غير صالح، رقمًا بلا كود دولة، كلمة تأكيد مختلفة، شروطًا دون موافقة، وCAPTCHA غير مكتملة.
- جرّب تواصل معنا باللغتين، عنوان شكوى قصير، ردًا فارغًا، وحدود أدمن خارج النطاق.
- جرّب استيرادًا دون عمود تواصل، أعمدة متكررة، منصة AI بلا مفتاح/موديل، وجدولة في الماضي.
- صحّح خانة واحدة وتأكد أن باقي الأخطاء لا تختفي.
- افتح تأكيد الهوية ثم أغلقه بـX أو Escape: لا يحدث تحويل أو فصل. وافق: يفتح Google ثم يعود لمسار الربط.
- راجع الهاتف والكمبيوتر، الوضعين الفاتح والداكن، Tab وShift+Tab، والتكبير 200%.
