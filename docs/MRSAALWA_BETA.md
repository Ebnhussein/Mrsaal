# MrsaalWA — تجربة محدودة للمستخدمين

MrsaalWA هو اسم واجهة OpenWA في مرسال، باستخدام محرك whatsapp-web.js. Baileys يظل الربط الحالي. الاختيار يُحفظ لكل مستخدم، ولا يوجد تحويل تلقائي عند فشل الإرسال.

## تجهيز السيرفر الحالي

1. احتفظ بنسخة من قاعدة مرسال وبيانات OpenWA. نسخة الكود السابقة على الفرع `backup/before-mrsaalwa-beta-20261016`.
2. من OpenWA: أوقف جلسة `mrsaal-trial` بزر **Stop** لتوفير المكان. لا تستخدم Delete أو Unlink إلا لو تقصد إزالة ربطها. الربط الجديد للمستخدم يُنشئ جلسة مستقلة؛ لا تنسخ Session ID التجربة لأي مستخدم.
3. أنشئ API Key مخصصًا للباك إند في OpenWA بدور يسمح **بإنشاء وإدارة الجلسات والإرسال وقراءة الحالات**. المفتاح المقيد بجلسة التجربة وحدها لا يصلح لإنشاء جلسات المستخدمين. لا تضع المفتاح في الواجهة أو GitHub.
4. في Coolify، مرسال، Runtime:

```env
MRSAALWA_ENABLED=true
MRSAALWA_BASE_URL=http://openwa-trial:2785
MRSAALWA_API_KEY=ضع_مفتاح_الخدمة_الفعلي
MRSAALWA_MAX_SESSIONS=1
OPENWA_TRIAL_ENABLED=false
```

ثم Save وRedeploy. اسم الشبكة الخارجية لازم يكون مشتركًا بين مرسال وخدمة OpenWA كما في التجربة. لا تنشر المنفذ 2785 للعامة.

حد البداية **جلسة واحدة محجوزة**، ويُحتسب أيضًا أي محرك آخر يعمل على نفس بوابة OpenWA عند بدء جلسة. السيرفر الحالي 5.8 GiB؛ نجاح تجربة واحدة لا يثبت استيعاب عدة متصفحات. لا ترفع الحد قبل قياس الموارد. إصدار Compose الجديد يستخدم 2g ويحافظ على نفس volume واسم الخدمة.

لتثبيت تعديل Compose على VPS بعد الدبلوي (الأوامر داخل Ubuntu):

```bash
mrsaal_app="$(sudo docker ps --filter name=lze8r5qbmjkxshreworyhtb8 --format '{{.Names}}' | head -n 1)"
sudo cp /home/ubuntu/openwa-trial/compose.yaml /home/ubuntu/openwa-trial/compose.before-mrsaalwa.yaml
sudo docker cp "$mrsaal_app:/app/ops/openwa-trial/compose.yaml" /home/ubuntu/openwa-trial/compose.yaml
sudo docker compose --project-directory /home/ubuntu/openwa-trial --env-file /home/ubuntu/openwa-trial/.env -f /home/ubuntu/openwa-trial/compose.yaml up -d --no-build
```

التغيير يعيد إنشاء حاوية OpenWA لحظيًا. بياناتها محفوظة. AUTO_START_SESSIONS=false: اضغط الربط في مرسال لبدء جلسة المستخدم بعد عودة الخدمة. إذا أردت زيادة الحد مستقبلًا، نسّق `MRSAALWA_MAX_SESSIONS` في مرسال وفي ملف `.env` لخدمة OpenWA، ووفّر RAM كافية أولًا.

## إتاحة الحسابات

- الأدمن يقدر يختار MrsaalWA عند تفعيل السيرفر.
- لوحة الأدمن ← المستخدمون ← الاستخدام والحدود ← **إتاحة MrsaalWA — تحت التجربة** ← حفظ.
- نفس النافذة تعرض طريقة الربط وحالتها وأحداث التجربة وإجماليات الإرسال.
- سحب الإتاحة يمنع الإرسال والربط الجديدين، بدون إرسال تلقائي من Baileys. الجلسة الموجودة تظل محجوزة حتى فصلها؛ راجع المستخدم وأوقف الحملات قبل الفصل.

## تجربة المستخدم

الإعدادات ← قنوات التواصل ← طريقة ربط واتساب:

- **واتساب — الربط الحالي**: Baileys وQR كما كان.
- **MrsaalWA · تحت التجربة**: يظهر للجميع، واختياره متاح للحسابات المسموح لها فقط.
- قبل تغيير الطريقة: يفصل المستخدم الربط القديم، وينهي الحملات النشطة/الجدولة ويفحص أي إرسال غير مؤكد في التقارير. التغيير لا ينقل بيانات تسجيل الدخول بين المكتبتين.
- QR: اختيار QR Code ثم ربط واتساب؛ يمسح الرمز من الأجهزة المرتبطة.
- الرقم: اختيار كود برقم الموبايل، كتابة رقم حساب واتساب بكود الدولة، والموافقة على التحذير. طلب كود قد يفصل جلسة مرتبطة قديمة لنفس الرقم؛ QR هو البديل للحفاظ عليها. من واتساب يدخل إلى الأجهزة المرتبطة ← ربط جهاز ← الربط برقم الهاتف، ثم يكتب الكود. إذا لم تُجهز الجلسة، يحدّث الحالة ثم يعاود طلب الكود بعد دقيقة. الكود لا يُسجل في قاعدة مرسال أو اللوج.
- تأكيد الهوية مطلوب قبل تغيير القناة/بدء الربط/الفصل، ثم يرجع المستخدم لنفس الإعدادات. الإرسال نفسه يتبع حدود مرسال الحالية.

## الإرسال والمتابعة

- الحملات والإرسال اليدوي والجدولة تستخدم الطريقة المختارة للحساب نفسه.
- النص يُهندم بنفس قواعد واتساب. PDF يُرسل كمستند واحد مع النص، حتى 10 MB وتعليق حتى 1024 حرفًا. ما يزيد يُرفض قبل الإرسال برسالة واضحة بدل قصه أو إرسال ملف ناقص.
- مرسال يحفظ provider وsession لكل إرسال MrsaalWA. قبول الخدمة ليس إثبات تسليم.
- المتابعة كل 30 ثانية بدفعات محدودة من الإرسالات خلال آخر 7 أيام، وقد تتأخر مع زيادة السجل. تستورد حالة التسليم/القراءة وردود المحادثات التي أرسل لها المستخدم من مرسال، دون نسخ صندوق محادثاته كله. وقت رصد القراءة هو وقت وصول الحالة لمرسال، وليس إثباتًا لوقت قراءة الإنسان بالثانية.
- تأكيد الإرسال المفقود يصبح «غير مؤكد»، لا يعاد تلقائيًا ولا يتحول للمكتبة الأخرى. حد الإرسال الموحد والحجز ومنع التكرار يبقون فعالين.
- القراءة تعتمد على إتاحة إيصالات القراءة من واتساب؛ لا نعد بظهورها لكل رسالة.
- زر بلّغ عن مشكلة يفتح تذاكر الدعم الحالية. أحداث الاتصال والإرسال في لوحة الأدمن لا تسجل المفاتيح أو الرسائل أو QR.
- حذف حساب مرسال يفصل ويحذف جلسة OpenWA المملوكة له أولًا؛ فشل التنظيف يمنع الحذف الكامل حتى المحاولة مجددًا.

## قائمة الاختبار قبل توسيع الإتاحة

- [ ] حساب غير مسموح: MrsaalWA ظاهر كتجريبي وغير قابل للاختيار، ومحاولة API المباشرة مرفوضة.
- [ ] حساب مسموح: فصل القديم، اختيار MrsaalWA، QR، اتصال، نص، PDF، رد، تقرير وإشعار.
- [ ] بعد فصل QR: الربط بالرقم والكود، مع اختبار صلاحية الكود على الموبايل.
- [ ] مستخدمان تجريبيان: لا يُعرض QR أو كود أو رقم أو سجل الحساب الآخر. الحد 1 يرفض تشغيل جلسة ثانية بوضوح.
- [ ] قراءة الرسالة من الكمبيوتر والموبايل الأساسي غير متصل، ومحادثة مع رقم جديد.
- [ ] إعادة تشغيل مرسال تحافظ على ملكية الجلسة؛ إعادة تشغيل البوابة ثم Connect لا تطلب QR إذا بيانات واتساب ما زالت صالحة.
- [ ] فشل/مهلة الإرسال لا يكرر الرسالة؛ مراجعة التقارير قبل المحاولة.
- [ ] رسالة طويلة مع PDF تظهر حد 1024 حرفًا قبل الإرسال ولا تفقد أي جزء بصمت.
- [ ] تغيير طريقة الربط أثناء حملة/جدولة/نتيجة غير مؤكدة مرفوض.
- [ ] تعليق المستخدم/سحب إتاحته يمنع الإرسال الجديد، ولا يحول الحساب لطريقة أخرى تلقائيًا.
- [ ] AR/EN، الموبايل، اللايت/الدارك، زر الدعم، وفحص CPU/RAM بعد كل جلسة.

للرجوع: افصل جلسة MrsaalWA أولًا بعد إنهاء الإرسال، اختار الربط الحالي، واربط QR جديدًا. تعطيل MRSAALWA_ENABLED وحده يوقف استخدام التجربة ولا يعيد ربط Baileys نيابةً عن المستخدم.

فحص الإعدادات والشبكة والسعة بدون طباعة مفاتيح أو أرقام، داخل حاوية مرسال الحالية:

```bash
sudo docker exec -w /app "$mrsaal_app" node ops/mrsaalwa-check.cjs
```


## تعطيل الحد الإجمالي للجلسات (2026-10-17)

القيمة الصريحة `MRSAALWA_MAX_SESSIONS=0` تلغي حد حجوزات الجلسات والمحركات في مرسال. الحسابات تظل معزولة ولكل حساب جلسته الخاصة؛ لا يتغير فحص الصلاحيات أو تأكيد الهوية أو حدود الإرسال.

ضع القيمة في تطبيق مرسال في Coolify ثم Redeploy. وضع القيمة نفسها في `/home/ubuntu/openwa-trial/.env` ثم أعد إنشاء الخدمة بواسطة Compose باستخدام `up -d --no-build`؛ إعادة التشغيل فقط لا تحمل متغيرات البيئة الجديدة. ملف Compose يمرر المتغير إلى `MAX_CONCURRENT_SESSIONS`، والصفر مدعوم كإلغاء للحد في نسخة OpenWA المثبتة `078b8aa458584762b9dee6d6e83fc42680fa14e5`.

عدم ضبط المتغير أو تركه فارغًا أو وضع قيمة غير صالحة يبقي الحد الافتراضي جلسة واحدة. القيم 1–50 تبقي حدًا إجماليًا صريحًا. فحص `ops/mrsaalwa-check.cjs` يعرض `maxSessions:0,unlimited:true` بعد التفعيل.

إلغاء الحد ليس زيادة للذاكرة: خدمة OpenWA الحالية ما زالت محدودة بـ2 GiB. امتلاء الذاكرة قد يوقف الخدمة والجلسات. زيادة التشغيل الفعلي تحتاج موارد واختبار حمل أو توزيع الخدمة؛ هذا التعديل يزيل المنع العددي فقط. لا تحذف أو تفصل جلسات المستخدمين لتطبيق الإعداد.

للتراجع: ضع حدًا موجبًا في التطبيق وفي بيئة الخدمة، ثم أعد نشرهما. تغيير الحد لا يفصل تلقائيًا جلسات قائمة تتجاوز الحد الجديد.
