# تجربة OpenWA وتحسين Baileys — 16 أكتوبر 2026

التجربة **مقفولة افتراضيًا**. الحملات والإرسال العادي يفضلوا على Baileys. واجهة التجربة مستقلة في الإعدادات ← قنوات التواصل، ولا تظهر إلا لبريد أدمن واحد تحدده بنفسك. الربط الحالي وبياناته لا تنتقل تلقائيًا.

النسخة السابقة محفوظة في `backup/before-whatsapp-trial-20261016`.

## 1. نشر تحديث مرسال

اعمل Redeploy من Coolify، وبعد اكتمال التشغيل حدّث الصفحة. تحسينات Baileys تعمل مع النسخة الجديدة مباشرة؛ تشغيل OpenWA يحتاج باقي الخطوات.

## 2. تجهيز خدمة OpenWA على الـVPS

نفّذ في SSH على Ubuntu. انسخ الأوامر فقط، من غير سطر `ubuntu@...`.

```bash
mrsaal_app="$(sudo docker ps --filter name=lze8r5qbmjkxshreworyhtb8 --format '{{.Names}}' | head -n 1)"
test -n "$mrsaal_app"
sudo install -d -m 700 -o ubuntu -g ubuntu /home/ubuntu/openwa-trial
sudo docker cp "$mrsaal_app:/app/ops/openwa-trial/." /home/ubuntu/openwa-trial/
sudo bash /home/ubuntu/openwa-trial/setup.sh
```

السكربت يبني خدمة مستقلة من مصدر OpenWA المثبّت على commit `078b8aa458584762b9dee6d6e83fc42680fa14e5`. البناء الأول ممكن يأخذ وقتًا؛ لوجاته تظهر في الطرفية. لا تحذف الحاويات أو الـvolumes لحل تأخير البناء.

الخدمة تستخدم `whatsapp-web.js` للمقارنة بمحرك مختلف. حدها جلسة واحدة، RAM حتى 1536 MB وCPU حتى 1.5 core وقت التشغيل. حد البناء منفصل عن هذه الحدود. قاعدة SQLite وبيانات الجلسة في volume خاص بالخدمة. لا يتم تركيب Docker socket، ولا فتح منفذ عام، ولا تعديل إعدادات Traefik أو Caddy.

### تأكد من الشبكة

الافتراضي شبكة Docker الخارجية `coolify`. تحقق إن مرسال مرتبط بها:

```bash
sudo docker inspect "$mrsaal_app" --format '{{range $name, $network := .NetworkSettings.Networks}}{{println $name}}{{end}}'
```

لو مرسال على شبكة مختلفة، عدّل `OPENWA_DOCKER_NETWORK` في `/home/ubuntu/openwa-trial/.env` لاسم الشبكة المشتركة الصحيحة، ثم شغّل setup.sh مرة أخرى. متغيرات الشبكة هنا تخص ملف compose، مش متغيرات تطبيق مرسال.

## 3. فتح لوحة OpenWA

على Windows PowerShell شغّل:

```powershell
ssh -N -L 2785:127.0.0.1:2785 -i "d:/projects/n8noracle/ssh-key-2026-09-28.key" ubuntu@84.13.147.245
```

سيب الطرفية مفتوحة، وافتح `http://localhost:2785` في المتصفح. ده نفق للإدارة فقط؛ بعد قفله التجربة بين مرسال وOpenWA على شبكة Docker تفضل شغالة.

المفتاح الأول محفوظ محليًا بصلاحيات 600 في `.env`. افتحه على السيرفر للنسخ إلى لوحة الإدارة عند الحاجة، **متبعتش محتواه في الشات أو اللوج**:

```bash
sudo nano /home/ubuntu/openwa-trial/.env
```

من لوحة OpenWA:

1. اعمل جلسة باسم `mrsaal-trial`.
2. احتفظ بالـsession UUID من تفاصيل الجلسة.
3. يفضل إنشاء مفتاح Operator محدود بالجلسة دي فقط لاستخدامه في مرسال. مفتاح الإدارة يظل لإدارة OpenWA.
4. اختار رقم واتساب تجريبي للربط، ورقم استقبال تاني تملكه أو معاك موافقة صاحبه للاختبار.

## 4. متغيرات Coolify في تطبيق مرسال

أضف القيم **Runtime**. استبدل الوصف بقيمك الفعلية؛ لا تنسخ وصف الجلسة أو المفتاح كقيمة:

| المتغير | القيمة |
| --- | --- |
| `OPENWA_TRIAL_ENABLED` | `true` |
| `OPENWA_BASE_URL` | `http://openwa-trial:2785` |
| `OPENWA_API_KEY` | مفتاح OpenWA المحدود بالجلسة التجريبية |
| `OPENWA_TRIAL_SESSION_ID` | UUID الجلسة اللي أنشأتها |
| `OPENWA_TRIAL_EMAIL` | بريد أدمن واحد موجود بالفعل في `ADMIN_EMAILS` |
| `OPENWA_TRIAL_RECIPIENT` | رقم الاستقبال التجريبي بكود الدولة، أرقام فقط بدون `+` |

اعمل Redeploy لتطبيق مرسال. ادخل بحساب Google الخاص بالأدمن المحدد. لو مر أكثر من 15 دقيقة على الدخول، زر بدء/إيقاف/إرسال التجربة يطلب تأكيد الهوية بالدخول من جديد.

الإعدادات ← قنوات التواصل ← **تجربة OpenWA — للأدمن**:

1. ابدأ الربط وامسح QR من الأجهزة المرتبطة على هاتف الرقم التجريبي.
2. انتظر ظهور «متصل».
3. راجع رقم الاستقبال الظاهر، واكتب رسالة اختبار. فعّل مرفق الـCV لو محتاج؛ لازم نسخة PDF نشطة حتى 10 MB.
4. فعّل موافقة استقبال الاختبار، واضغط إرسال مرة واحدة.
5. افتح المستلم، وبعدها اضغط «تحديث الوصول والردود». جرّب الرد من الرقم المستلم.

قبول الإرسال لا يثبت الوصول. الحالات تظهر حسب البيانات التي رصدها OpenWA. الواجهة تعرض آخر 20 رسالة من **محادثة رقم الاختبار فقط**؛ الاختبارات لا تظهر في تقارير حملات مرسال.

كل محاولة إرسال تبدأ فعليًا تُحجز مرة في جدول `openwa_trial_attempts` الخاص بالتجربة؛ الحد 5 محاولات خلال 24 ساعة، ويشمل المحاولات غير المؤكدة. إعادة نفس المفتاح لا ترسل مرة ثانية، حتى بعد إعادة تشغيل مرسال. لا توجد إعادة إرسال تلقائية عند المهلة أو فقد رد الخدمة. «تجهيز اختبار جديد» خطوة صريحة، فلا تستخدمها قبل مراجعة المحادثة لو النتيجة غير مؤكدة.

### فحص الاتصال بدون إرسال

بعد تحديد حاوية مرسال الجديدة في `mrsaal_app`، نفّذ:

```bash
sudo docker exec -w /app "$mrsaal_app" node ops/openwa-trial/check.cjs
```

النتيجة تعرض الحالة فقط؛ لا تطبع المفاتيح أو QR أو محتوى الرسائل.

## تحسينات Baileys في هذا التحديث

- حدث قطع الاتصال المتكرر يجدول محاولة واحدة فقط؛ بدون مقابس متوازية لنفس الحساب.
- الاتصال الذي يفتح ثم يقفل بسرعة يحتفظ بميزانية المحاولات؛ تصفيرها بعد اتصال مستقر لمدة دقيقة.
- انتظار كتابة مفاتيح الجلسة قبل إعادة فتح الاتصال، وحفظ الكتابات المنتظرة عند الإغلاق الهادئ.
- التحقق من ثبات نفس الاتصال بين فحص الرقم وتجهيز الرسالة وحفظها والإرسال.
- مهلة فحص الرقم 20 ثانية، مع تمييز الفشل الذي حدث قبل الإرسال عن نتيجة الإرسال غير المؤكدة.
- فقد رد الإرسال لا يؤدي لإعادة الإرسال تلقائيًا أو اعتباره فشلًا مؤكدًا.
- أسباب أخطاء مفهومة بالعربي والإنجليزي، وبيانات تشخيص حالة الاتصال من غير طباعة مفاتيح الجلسة.

الإصدار المستخدم يظل `@whiskeysockets/baileys@6.7.24`. نقل 7.x يحتاج فحص توافق مستقل؛ لا نخلطه بتجربة المحرك الثاني.

## إيقاف التجربة

اضغط «إيقاف التجربة» ثم غيّر `OPENWA_TRIAL_ENABLED=false` في Coolify واعمل Redeploy. مفتاح الربط الحالي لـBaileys والحملات لا يتغيروا.

لإيقاف الخدمة نفسها بدون حذف بياناتها:

```bash
sudo docker compose --project-directory /home/ubuntu/openwa-trial --env-file /home/ubuntu/openwa-trial/.env -f /home/ubuntu/openwa-trial/compose.yaml stop
```

لا تستخدم `down -v`؛ ده يحذف بيانات التجربة. بيانات OpenWA ومفاتيحه تحتاج نسخًا احتياطية منفصلة قبل أي استخدام يتجاوز الاختبار.
